# Agora

A decentralized social app on **AutonomousTrust** — profiles, connections, a
feed, and (later) businesses as **Ethne** polities, with no central server,
identity provider, or policy authority.

> **A person is an AutonomousTrust node. A business is an Ethne polity.**

Full design: [`doc/agora/design.md`](doc/agora/design.md).

## Status

**Phase 0 + RTT proximity — Linux (verified); macOS and Windows ported,
awaiting their first build on a Mac and on Windows (see [macOS](#macos),
[Windows](#windows)).** A live "people near me" view driven
by the AutonomousTrust **C** core, showing each observed peer's short id, rank,
**operator-attended presence**, **reputation**, and **RTT** (round-trip time, ms).
RTT is a network-latency **proximity proxy**, not geographic distance. Profile
fields (`agora.profile`) and true geographic distance are **not** shown yet — see
the gap note under Architecture.

## Architecture

Agora drives the **AutonomousTrust C core directly (no Python)** behind a
**Flutter** UI via `dart:ffi`. The authoritative record of this decision and its
constraints is **[`doc/agora/design.md` §5.1](doc/agora/design.md)**
("Runtime & client architecture (decided)"). In brief:

- **`native/agorad`** — a standalone daemon that runs the AT node in its own
  process (calls `run_autonomous_trust`). The Flutter GUI process therefore
  never `fork()`s.
- **`native/libagora_shim`** — a flat, union-free FFI surface over AT's
  fork-free app-events client (`at_app_events_*`).
- **`at-social/`** — AT's social extension (`libat_social`, the
  `autonomous_trust.social` Python distribution, and the `social` conformance
  protocol), which Agora owns. The native build hands it to AT as an external
  extension; see [`at-social/README.md`](at-social/README.md).
- **`lib/` (Dart)** — FFI bindings, the merged `AgoraPeer` model, the daemon
  supervisor, a poll loop, and the UI.

**Known gap (partly closed):** AT's C event surface now exposes peer, reputation,
and **RTT** events (`AT_APP_EVENT_PEER_RTT` — the first proximity increment, a
network-latency proxy). Still deferred to AT-core: `agora.profile` fields and
**true geographic position/distance**, so the plan's geographic Dunbar mechanism
still waits on a further AT-core event kind. RTT is a latency proxy, never
surfaced as distance. (`doc/agora/design.md` §5.1.)

iOS and Android are follow-on ports. The AT-core work they need (the
in-process runtime: subsystems as threads, `AT_IN_PROCESS`) now exists, built
for Windows.

## Layout

```
native/          C: agorad daemon + libagora_shim (+ builds the AT C core)
at-social/       AT's social extension: c/social (libat_social), python/,
                 conformance/ (AT harness plug-in), test-conformance.sh
lib/
  main.dart
  src/ffi/       dart:ffi bindings + AgoraPeer model
  src/node/      agorad supervisor + poll loop
  src/ui/        People near me view
test/            pure-Dart model/decode tests
linux/ macos/    Flutter desktop runners (generated by `flutter create`)
```

## Build & run (Linux — verified)

Prerequisites: a C toolchain + CMake ≥3.23, the AT C deps
(`libsodium jansson uuid protobuf-c protobuf openssl`), the Flutter SDK, and (for
`flutter build linux`) `ninja-build libgtk-3-dev clang`. The AT C core is a
submodule — run `git submodule update --init --recursive` first.

### Quick start

```bash
./setup.sh            # this OS's toolchain, deps, Rust, Flutter (one-time)
./build.sh            # native layer + Flutter app (default: linux/x86_64)
./build.sh macos      # on a Mac
./test.sh             # flutter analyze + pure-Dart unit tests
./run-dev.sh          # build for this OS (Linux, macOS, Windows) and flutter run
```

Agora builds entirely with the **system toolchain** — **conda is not used for the
build** (mixing a conda env with the system GTK stack breaks the Flutter build).
`setup.sh` detects the OS (as `run-dev.sh` does) and installs what it can,
listing anything it cannot (Xcode, Visual Studio without winget) as manual steps
and exiting 1. On Linux it installs from apt (or dnf, pacman): the C/C++ toolchain, CMake/Ninja/pkg-config,
the AT C-core deps (libsodium, jansson, uuid, protobuf, protobuf-c, openssl), the
Flutter Linux desktop toolchain (GTK), Rust (rustup), and the Flutter SDK. No conda activation is
needed; if a conda env happens to be active, `build.sh` strips it for a clean
system build (override with `AGORA_KEEP_CONDA=1`). conda remains fine for the
AutonomousTrust *Python* inspector/services — it is simply off the Agora build path.

`build.sh` env knobs: `AGORA_STRICT=1` (keep AT's `-Werror`), `BUILD_TYPE`
(native CMake type), `FLUTTER_MODE` (`--debug`/`--profile`/`--release`).

### Or step by step

```bash
# 1. Build the native layer (AT core + shim + daemon; DTN/ZTA stay OFF).
#    The two flags handle newer-than-AT-tested toolchains on fuse/virtio FS:
#    cc-no-werror.sh strips AT's hardcoded -Werror; AT_CC_VALIDATE_OUTPUT=OFF
#    stops AT overriding our compiler launcher. On AT's tuned toolchain both
#    can be omitted.
cmake -S native -B native/build -DCMAKE_BUILD_TYPE=Release \
  -DAT_CC_VALIDATE_OUTPUT=OFF \
  -DCMAKE_C_COMPILER_LAUNCHER="$PWD/native/cc-no-werror.sh" \
  -DCMAKE_CXX_COMPILER_LAUNCHER="$PWD/native/cc-no-werror.sh"
cmake --build native/build --target agorad agora_shim -j"$(nproc)"

# 2. Flutter deps + desktop runners (already generated in-repo)
flutter pub get

# 3. Pure-Dart tests need NO native build:
flutter test                       # 4/4 pass

# 4. Build the app. When the native layer (step 1) is already built, its
#    artifacts (agorad, libagora_shim, libautonomous_trust, and the extension
#    libraries: the five libat_<layer> verification layers and libat_social)
#    are copied into the bundle's lib/ dir, so the built bundle runs
#    self-contained.
flutter build linux --debug        # -> build/linux/x64/debug/bundle/agora

# 5a. Run the packaged bundle directly — no env vars needed; the Dart layer
#     finds agorad + the shim in the bundle's lib/ dir.
./build/linux/x64/debug/bundle/agora   # needs a display

# 5b. Or `flutter run` against the native build tree (dev iteration). The Dart
#     layer honors these env vars; LD_LIBRARY_PATH lets libagora_shim find
#     libautonomous_trust.
export AGORA_DAEMON_PATH="$PWD/native/build/agorad"
export AGORA_SHIM_PATH="$PWD/native/build/libagora_shim.so"        # .dylib on macOS
export LD_LIBRARY_PATH="$PWD/native/build/at_core:$LD_LIBRARY_PATH"
flutter run -d linux               # needs a display; -d macos on a Mac
```

**Packaging:** `./package-appimage.sh` turns the release bundle into an
AppImage for other Linux machines; `./package-dmg.sh` is the macOS counterpart.

## macOS

Everything a Mac build needs is in the tree; it has been cross-compiled and
linked for arm64 macOS from Linux, but not yet built, run or signed on a Mac.
Flutter cannot cross-compile desktop apps, so the build runs on the Mac itself.

Download/install 


```bash
./setup.sh            # Homebrew + deps, Rosetta, Rust, Flutter; Xcode is manual
./build.sh macos      # native layer + agora.app, for this Mac's architecture
./test.sh             # analyze + unit tests (+ integration once native is built)
./run-dev.sh          # build the native layer for this OS, then flutter run
./package-dmg.sh      # a .dmg for other Macs (SIGN_IDENTITY / NOTARY_PROFILE to distribute)
```

- **Dependencies** come from Homebrew: `cmake ninja pkg-config libsodium jansson
  protobuf protobuf-c` (and Rust, optional, for businesses). libuuid is part of
  macOS; do not install `ossp-uuid`, whose `uuid.h` is a different API.
- **The bundle.** The Runner's "Embed Agora Native" build phase
  (`macos/embed_native.sh`) puts `agorad` in `Contents/MacOS` and the shim, the
  AT libraries and every Homebrew dylib they load in `Contents/Frameworks`, with
  `@rpath` install names, then signs them. The app needs no Homebrew to run.
- **One architecture.** Homebrew bottles are single-arch, so the native layer is
  built for the Mac doing the build; the app runs on Macs of the same kind.
- **No App Sandbox.** The app spawns `agorad`, which binds unix sockets under its
  data root and joins LAN multicast; it is distributed outside the App Store,
  signed with a Developer ID and notarized (`package-dmg.sh`). Node state lives
  in `~/Library/Application Support/Agora`.
- **Not on a Mac:** the live cohorts under `test/cohort/` (they need Linux
  network namespaces).

## Windows

Built with MSYS2's UCRT64 toolchain, native (no Cygwin runtime): agorad and the
AT libraries are ordinary Windows programs and DLLs, and the Flutter runner is
Visual Studio's. Cross-compiled and tested from Linux (zig, Wine), not yet
built or run on Windows.

Download/install MSYS2: https://www.msys2.org


```bash
# in an "MSYS2 UCRT64" shell
pacmac -S git
git clone --recurse-submodules <repo> && cd <repo>
./setup.sh            # pacman packages + Rust, VS Build Tools (winget), Flutter
./build.sh windows    # native layer + agora.exe
./test.sh             # analyze + unit tests (+ integration once native is built)
./run-dev.sh          # build the native layer for this OS, then flutter run
./package-windows.sh  # a .zip for other PCs (SIGN_CMD to sign)
```

- **No fork.** Windows has neither fork nor unix datagram sockets, so AT runs
  its subsystems as threads of agorad (the in-process runtime, AT
  `AT_IN_PROCESS`; Linux and macOS can run it too, `AT_IN_PROCESS=1`). The
  subsystems talk over in-process queues; the app reaches agorad over an
  AF_UNIX stream socket (Windows 10 1803+) under its data root.
- **Stopping.** Windows has no SIGTERM: the app stops agorad by closing its
  stdin, and agorad also stops by itself if the app dies.
- **The bundle.** `windows/CMakeLists.txt` copies agorad.exe, the shim, the AT
  DLLs and every MinGW DLL they load (from `AGORA_MINGW_BIN`, which `build.sh`
  sets) beside agora.exe. Node state lives in `%LOCALAPPDATA%\Agora`.
- **Not on Windows:** the live cohorts under `test/cohort/` (Linux network
  namespaces).
